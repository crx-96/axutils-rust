# 资源、运行时与安全

结构复用优先考虑普通泛型和共享纯逻辑；trait object、`async_trait`、boxing 或缓存以当前设计
需求和收益为依据。性能驱动的改动用测量检验，不因少量重复引入额外间接层；性能比较方法见
[develop 的性能测量章节](../../../develop.md#性能测量)。

解析、网络、加密、缓存、锁、任务和全局状态发生变化时，沿受影响路径评估相关问题：

- 时间/空间复杂度、临时分配和复制。
- 输入、文件、递归、模板展开、批量、缓存、重试、超时和并发上限。
- 锁竞争、跨 await 持有资源、取消、关闭和租约语义。
- 错误/日志中密钥、token、凭据、配置、Header、明文和原始响应的泄露风险。

全局入口按 [架构基线](../../../architecture.md#状态与能力隔离) 验证成功、重复初始化、并发竞争、
失败不占位、成功后不可替换、实例访问和关闭后行为。普通异步 API 避免隐式创建 runtime 或
`block_on`；配置/客户端构造默认不访问网络，接口确实设计为访问网络时，在 API doc 和测试中
说明副作用。

时间与数量参数不仅检查零值，也检查到后端类型、deadline、容量或计数的转换是否可表示。
配置驱动的失败应在发布任务或执行 I/O 前按契约返回错误，避免先报告成功，再由后台算术溢出或
panic 使任务消失。异步接口说明取消后是否保留部分写入、在途请求或后台任务；取消请求、等待完成
和资源实际释放分别验证，不能以丢弃 handle 推断工作已经停止。

登记/协调状态使用的短临界区只维护内部元数据；提交任务、释放用户持有的 callback/future 和
调用用户代码时，核对是否可能同步析构或重入。资源专用异步锁可按初始化或协议串行化的实际需要
跨越 await，但须核对取消、超时与互斥语义。锁外提交仍须保证容量、关闭、取消与发布的线性化，
不让已取消或完成的登记重新出现。通知可能早于 waiter 的第一次 poll，关闭协议需要保存这一状态
或通知许可。

校验应覆盖所有等价入口，并在 URL 等解析器可能删除、转义或规范化原输入之前完成必要的原始输入
检查。上游池、批量路由和日志默认值也属于契约的一部分：应用承诺的连接生命周期、原子/slot 边界、
并发配额及脱敏不能仅由本库的参数名称或自己的 telemetry 推断，应核对后端实际执行方式。

领域安全语义：

- 错误和日志省略 AES 密钥、明文、IV/nonce 的实际值；MD5 用于非安全摘要，不适用于密码或签名，
  CBC 不提供认证加密。
- `RandomUtils` 是非密码学随机工具；安全密钥和 nonce 使用操作系统随机源。
- JWT payload 是可读取内容；算法、key、时间和解析预算边界在接口与测试中明确。
- 配置错误使用脱敏诊断；网络能力按影响审查代理、重定向、TLS、SSRF、重试与大小限制。
- Config/JWT 安全预检、HTTP 顺序/缓存、Redis 锁/事务、Scheduler 锁和 Crypto 临时 buffer 等
  既有语义，以问题证据、已授权目标和对应回归为变更依据。
