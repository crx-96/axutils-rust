# axutils Rust library 变更与验收

本 Skill 保存项目实现、审查和重构的流程。先遵循 [AGENTS](../../../AGENTS.md) 与必读的
[personal](../../rules/personal.md)；个人风格不在本 Skill 重复定义。实际版本与能力以 manifest
为准，运行命令和环境处理集中在 [develop](../../develop.md)。

## 选取相关依据

| 当前影响 | 阅读入口 | 要取得的证据 |
| --- | --- | --- |
| 领域归属、目录拆分和跨模块依赖 | [架构](../../architecture.md)、[模块映射](../../module-map.md) | 职责、状态所有者、可见性与典型调用链 |
| API、错误类型、兼容性、feature/依赖 | [API 与 feature](references/api-and-features.md) | 原调用方、正负 fixture、依赖边界 |
| I/O、解析、并发、全局状态、加密 | [资源与安全](references/runtime-and-safety.md) | 正常/失败/取消行为、预算、脱敏与资源释放 |
| 测试、示例、API doc、版本和发布包 | [验证与文档](references/verification-and-docs.md) | 可观察契约、示例实际调用、包清单与迁移说明 |

按影响组合主题；已有有效上下文不重复读取。纯规则、格式和措辞维护检查原意、归属与关联链接，
不因此启动全库 Rust 测试。用户明确要求全库重构或审查时，覆盖所指定的全部工作面。

## 实施流程

1. **建立当前基线。** 确认工作区修改归属、受影响公共入口、调用方与测试。在改变测试前先运行
   相关原回归；跨领域重构使用 develop 的完整非 live 集合，包含 feature matrix 和 Markdown
   harness。失败先区分代码、用例和环境，不能把跳过或权限失败记录成通过。保留原断言语义，
   不用修改测试掩盖既有问题；若用户授权了契约迁移，记录新旧行为及其验证对应关系。
2. **先确定职责再移动。** 以独立变化原因、依赖和状态所有权选择边界，维护 canonical path、
   feature gate 与最小内部可见性。一次移动一个可解释的职责，核对直接调用方及资源释放路径；
   结构移动和行为修复应能从 diff 与回归中分别识别。字段、定义及处理步骤的注释按 personal
   同步维护，不用增加空壳模块或转发层制造结构一致性。
3. **用证据修复遗漏。** 沿当前领域的输入、转换、I/O、错误、并发与取消路径审查。
   对已确认缺陷补能检出原问题的回归，尽可能先在原实现上确认失败再修复；保留边界和负向用例。
   构造/解析/本地校验优先使用无外部副作用的测试，需要协议交互时使用 loopback fixture。
   不改变已有 API 来绕过实现困难，不凭重构引入额外功能、后端或依赖。
4. **整合后同步与验收。** 按最终实现更新 API doc、领域示例、模块映射和适用的 CHANGELOG；
   架构或协作规则只在其职责发生变化时更新。运行与整体改动相称的 develop 检查，确认原测试、
   新回归、能力隔离及示例覆盖一致。发布级变化增加 Rustdoc 与本地包检查；依赖版本、平台和
   MSRV 的结论必须对应实际运行环境。有效结果可复用，新改动或证据缺口再触发追加检查。

已有授权内直接实施；公共契约或外部影响存在实质未决选择时，按 AGENTS 与当前用户指令处理。
普通实现选择无需额外例外报告，真实服务和发布操作仍受各自授权边界约束。

## 审查与交付

源码、manifest、diff、测试诊断、依赖树和包清单用于证明当前行为；规则和用户目标用于判断行为
是否正确。文档不一致时先查明事实，不直接让测试迁就文档或让文档掩盖缺陷。

- **已确认问题**：给出触发条件、源码位置、影响及证据，并说明修复和回归。
- **规范差距**：区分历史布局/风格与真实契约缺陷，说明本次涉及的处理范围。
- **改进建议**：说明具体收益、代价和适用条件，不将可选偏好报告成必修故障。
- **未验证项**：明确未运行的平台、MSRV、live 或组合；负向用例须匹配目标诊断。

交付以实际完成项和剩余风险为准。维护本 Skill 时检查三个主题参考以及架构、module map、
develop 和 personal 的直接关联；规则保留唯一正文，历史修复事实留在 CHANGELOG 与回归中。
