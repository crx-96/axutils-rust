# axutils Rust library 变更审查与验收

本 Skill 维护库级契约和质量判断。架构约定集中在 [architecture](../../architecture.md)，
当前模块与能力映射见 [module map](../../module-map.md)，命令与运行条件见
[develop](../../develop.md)，协作和仓库边界见 [AGENTS.md](../../../AGENTS.md)。

## 按影响选用主题

先确定目标源码、领域入口、调用方和受影响的测试/fixture、API doc、示例与发布内容。涉及版本、
MSRV、feature 或依赖时核对 manifest。按当前改动选择下列主题；跨边界变化合并关注点，
已有上下文足够时不重复读取，普通维护不因此启动全库审计。

| 任务或影响面 | 设计依据 | 对应证据 |
| --- | --- | --- |
| 新增领域、模块归属、目录与文件拆分 | [架构基线](../../architecture.md) | 入口、依赖方向、内部可见性和原行为回归 |
| API、错误类型、兼容迁移、路径风格、feature/依赖 | [API 与 feature](references/api-and-features.md) | 相关调用方、正负 fixture、依赖树、文档 |
| I/O、并发、全局状态、解析、网络、加密、性能 | [资源与安全](references/runtime-and-safety.md) | 边界/失败/取消回归、资源约束、脱敏或测量 |
| 测试、示例、API doc、CHANGELOG、发布内容 | [验证与文档](references/verification-and-docs.md) | 契约覆盖、示例实际调用、诊断、发布清单 |

纯规则或 Skill 维护检查指令原意、职责归属与受影响链接；规范维护本身不要求 Rust 全量验证。
任务同时要求架构或库契约审查时，仍按实际影响选用上述依据。

## 审查与交付

以源码、manifest、diff、编译/测试结果、诊断、依赖树或发布清单支持结论。源码和可复现结果
说明当前行为，用户目标与规范用于判断行为是否正确；文档与实现不一致时先查明原因。

规范审查区分：

- **已确认问题**：违反现有公共契约或适用规则，附规则与代码位置、触发条件、影响及已有证据。
- **规范差距**：既有实现与新增约定不同，说明是否影响本次工作，不自动扩大为全库改造。
- **改进建议**：说明具体维护或使用收益、成本与适用条件，不把偏好写成现存缺陷。
- **未验证项**：标出缺少的矩阵、平台、MSRV、live 或其他证据；推断与事实分开。

交付对照用户目标说明实际变更与验证范围，核对行为回归、安全弱化、外部副作用和无关改动。
用例 ignored、负向用例的非目标编译错误、仅高版本工具链通过及局部构建成功，均不能替代所缺的
契约证据。设计建议可采用等效方案，涉及契约或剩余风险的取舍说明理由；普通实现选择无需
另写例外报告。权限、外部操作及未决选择按 AGENTS 处理。

维护本 Skill 时检查主题参考、架构、module map 和 develop 的受影响引用。每条详细规则保留
一个维护位置；历史迁移事实留在 CHANGELOG 和相关回归，不累积为所有后续任务的固定步骤。
