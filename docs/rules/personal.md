# axutils 项目个人规则

本文件保存用户已确认在本项目长期保留的个人风格与协作偏好，适用于整个仓库。
工程事实、公共契约和验证命令分别维护在架构、开发文档及项目 Skill 中；本文件不取代它们。
用户明确要求长期保留或调整的偏好在此合并维护，一次性任务要求不自动升级为永久规则。

## 中文与注释

- 沟通、审查意见、注释、文档和提交信息默认中文；标识符、API、命令和标准技术术语保留原文。
- 非测试手写源码的每个函数、方法、类型、结构体、字段、枚举成员和常量都在定义处说明用途与
  语义，包括私有辅助实现。优先使用 `///` / `//!`，根据实际契约补充单位、可选含义、默认值、
  边界、错误、副作用、所有权及生命周期；不机械翻译名称或复述参数类型。
- 实现中的校验、转换、分支、循环、状态迁移、并发、重试、取消及清理等独立处理阶段，就近解释
  目的、执行顺序和失败路径。同一阶段可以共用一段说明，纯导入和明显直接赋值无需逐行注释。
- 修改源码时同步检查本次涉及的定义、实现及理解它们所必需的直接上下文，补齐遗漏并修正过时
  注释。说明必须与实现一致，不用模板、行数或注释比例代替语义核对。
- 测试、fixture、mock 和测试专用辅助代码不要求批量补注释；生成物、第三方源码和不支持注释
  的格式按来源维护。生产代码即使被测试调用，也适用上述要求。

## 路径与目录风格

- 用 `use` 明确导入来源，普通表达式和签名使用简短路径；通用函数保留有领域含义的模块限定符，
  名称冲突时使用明确别名。保留现有 Clippy 长绝对路径约束，具体阈值以 `clippy.toml` 为准。
  负向 fixture 的目标表达式可直接写待验证的完整路径。
- 保留领域类型与工具入口分离的使用风格，不平铺根级类型、不增加 `prelude` 或兼容别名。
  实际 canonical path 和可见性契约以 [架构基线](../architecture.md#固定边界) 为唯一维护位置。
- 按职责、状态所有权、独立变化原因和测试边界拆分；类型、常量及小辅助函数靠近语义所有者。
  不设文件行数硬上限，不为每个类型创建文件，不为缩短文件制造空壳层或透传链。

## 协作与文档

- 已有授权内，证据足够即推进实施与验证；只有无法自行解决且实质改变公共契约、数据、成本或
  外部影响的选择再询问。保留用户修改，以当前需求证明新增抽象、依赖及结构调整的必要性。
- 每项规则保留唯一正文，入口通过链接定位；个人偏好、工程规范和可复用流程各自维护。
  工程事实变化时同步其来源，不用个人偏好覆盖错误或过时的规范。
- 默认在会话交付实际变更、验证结果、未验证项和剩余问题；不额外生成报告、diff 副本、审阅快照
  或打包副本。任务明确要求的正式成果及必要项目文档照常维护。
